## Micro-Plan (11 Steps)

### Part A: Add `test_cli_parent_flag_to_layout` Integration Test

**Step 1**: Create test scaffold in `tests/integration_tests.rs` (after line 346)
- Allocate unique socket path (e.g., `/tmp/swayve_test_parent_cli.sock`)
- Spawn listener and daemon tasks
- Set up event and command channels

**Step 2**: Register parent agent via socket
- Connect UnixStream to socket
- Send `AgentIPCMessage::Register` with parent agent (no parent_agent_id)
- Match on parent's mark and app_id

**Step 3**: Register child agent via socket with parent
- Send second `AgentIPCMessage::Register` with child's parent_agent_id set to parent's AgentId
- Flush stream

**Step 4**: Send synthetic window-created event for parent
- Use `event_tx.send(DaemonEvent::Sway(SwayEvent::WindowCreated { ... }))` for parent's con_id and app_id
- Small delay for daemon to process

**Step 5**: Send synthetic window-created event for child
- Send second event with child's con_id and app_id (different from parent)
- Small delay

**Step 6**: Verify LayoutManager hierarchy commands from sway_cmd_rx
- Loop through received commands (timeout per cmd ~500ms)
- Assert on SplitHorizontal with parent's mark
- Assert on MarkWindow for children container (mark_children_parent_1 pattern)
- Assert on SetLayoutTabbed for children container
- Use similar validation pattern as `test_subagent_layout_routing` (lines 174–199)

**Step 7**: Clean up (abort handles, remove socket file)

**Step 8**: Add `Focus` variant to DaemonEvent enum in `src/daemon.rs` (line 72–75)

- Send via Unix socket connection; let daemon's Focus handler do the work
- Alternative (simpler): Keep CLI independent for now (no socket wiring required by spec), but add daemon event handler in daemon.rs for future CLI wiring

## Key Decisions & Assumptions

- **Focus variant data**: Simplest approach is `Focus` with no data; handler queries state.agents directly. If CLI sends focus events, can add agent_ids later.
- **CLI-daemon wiring for focus**: Spec says "wire into daemon event loop" but doesn't mandate CLI→daemon socket communication. Can add IPC message type later (Wave 4). For now, add daemon handler as foundation.
- **Test reuses existing pattern**: Follow `test_subagent_layout_routing` structure; expected commands are same (SplitHorizontal, MarkWindow, SetLayoutTabbed).
- **No LayoutManager changes**: Test validates existing hierarchy logic; daemon integration is the new piece.

## Risk & Mitigation

| Risk | Mitigation |
|------|-----------|
| Focus handler may interfere with layout logic | Focus is parallel path; no shared state mutation except con_to_agent tracking (safe) |
| Test timing (daemon processing events) | Use small delays (50–100ms) between IPC sends and event sends, as existing tests do |
| Socket file cleanup | Use fs::remove_file in test cleanup; test isolation via unique socket paths |
