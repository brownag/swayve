# 28.2.2 -- one writer function for full and diff subscriptions (G81)

## Goal
Replace the two copy-pasted detached writer loops in `handle_client` with one `subscriber_writer(rx, writer)` function that owns the receiver and the socket write, so a writer whose socket has closed ends and drops its receiver, for both subscription modes.

## Notes
- **Duplicated code.** `src/daemon.rs:472-507`, the `SubscribeStatus` and `SubscribeDiff` arms of `handle_client`, are byte-identical except for the `DaemonEvent` variant.
  - Each does the same `mpsc::channel(32)`, `event_tx.send`, `writer_opt.take()`, and a detached `tokio::spawn` with the same `recv` / `write_all(msg)` / `write_all(b"\n")` loop.
  - Mode is already decided daemon-side, by `Subscriber.mode` and the `broadcast_status` and `broadcast_diff` formatting. So the writer needs no mode parameter. The caller's choice of event variant is the whole mode selection.
- **`src/cli.rs:593-614` is not a writer loop.**
  - It is the client-side poll in `register_and_wait`.
  - Coordinator confirmed: no `src/cli.rs` edit. The task touches `src/daemon.rs` only.
- **Behavior.**
  - A write failure after the peer closes ends the writer. The dropped `rx` then closes the channel, so `broadcast_status` and `broadcast_diff` prune the subscriber (`TrySendError::Closed`, `is_closed` in 28.2.1).
  - Half-close by the client does not end the subscription. There is no read-EOF signal and no oneshot (coordinator decision, shell clients).
- **Known limit, accepted scope.**
  - A writer with an idle channel only notices a closed socket on its next write.
  - An unchanged diff subscriber whose writer is idle may therefore stay in the subscriber list until the next write.
- **Constraints honored.**
  - The wire format and the `subscribe` / `subscribe_diff` method names are unchanged.
  - No new message kind and no resync protocol.
  - Both overflow policies are untouched: `broadcast_status` retains a full channel, and `broadcast_diff` sets `needs_snapshot`.
  - Channel capacity stays 32.
- **Tests.** `UnixStream::pair()` needs no path, so H10 (`unique_path`) does not apply to the new unit tests. `tests/subscribe_golden.rs` and `tests/slow_consumer.rs` stay unmodified.
- **Process.** No commit and no edit to `planning/STATE_28.md`. HEAD is `04da0d4`, which contains `17c72ce`, so the base check passes.
