## Notes
- `AgentId` derives `Hash, Eq, Clone`: usable as map key.
- `AgentWindow` derives only `Debug, Clone, Serialize, Deserialize` (no `PartialEq`); `AgentStatus` has `PartialEq`. Adding `PartialEq` to `AgentWindow` is outside Files-in-scope (types.rs enum only). Plan: compare via `serde_json::to_value(a) != serde_json::to_value(b)` inside daemon.rs; no types.rs change. (Cost: per-agent serialization per diff subscriber; fine at measured N.)
- `broadcast_status` is called at 4 sites (310, 334, 432, 457); having it also invoke `broadcast_diff` means no call-site edits and diff subscribers get updates on every change.
- Full path bytes unchanged: same `serde_json::to_string(&Vec<&AgentWindow>)`, same retain rules. Serialization of the full list is skipped if there are no Full subscribers is NOT done (keep it simple; behavior identical).
- Snapshot on first send: new entry has `needs_snapshot = true`, so it covers "first send".
- Diff sent: updated only on `Ok`; dropped frames leave `sent` stale but `needs_snapshot` forces a full replace next time.
- Empty-delta skip happens before try_send, so an idle snapshot-needed entry always sends (even with zero agents: snapshot with empty upsert, which is correct for client reset).
- No new tests required by the task beyond keeping existing ones passing; I will not add unrequested tests (ponytail), but one small diff test is cheap if the orchestrator wants it (Q1).
