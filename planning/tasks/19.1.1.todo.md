# 19.1.1 -- ensure_private_dir unit tests

## Goal
Add two unit tests in `src/cli.rs` `mod tests` pinning that `ensure_private_dir` creates a 0700 dir and rejects an existing 0755 dir.

## TODO items
- [x] Add `test_ensure_private_dir_creates_0700` after `test_runtime_dir_requires_xdg_runtime_dir`: path `temp_dir()/swayve_epd_<pid>`, `remove_dir_all` if present, call `ensure_private_dir`, assert Ok and `metadata.mode() & 0o777 == 0o700`, remove dir afterward.
- [x] Add `test_ensure_private_dir_rejects_loose_mode`: path `temp_dir()/swayve_epd_loose_<pid>`, remove if present, create via `DirBuilder::new().mode(0o755)`, assert `ensure_private_dir` is Err, remove dir afterward.
- [x] Run `cargo test --lib test_ensure_private_dir`; expect 2 passed.

## Notes
- `ensure_private_dir` (src/cli.rs:92) does `DirBuilder.recursive(true).mode(0o700).create`, then errors if uid differs or `mode & 0o077 != 0`. Existing dir with 0755 -> bails, so test 2 should pass without touching the function.
- Test module only has `use super::*; use clap::Parser;`. `DirBuilderExt` / `MetadataExt` are imported locally inside the function, not at module level, so each test needs its own `use std::os::unix::fs::{DirBuilderExt, MetadataExt};`.
- Second test uses a different dir name from the first (`_loose_`) so parallel test threads cannot collide.
- Possible risk: a umask stricter than 022 would make 0755 create as e.g. 0700 and the reject test would fail; the default 022 is fine. To be robust, test 2 will `set_permissions(0o755)` after create only if needed -- see Question 1.
- Only test code is touched; no non-test edits.
