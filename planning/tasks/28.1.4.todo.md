## Notes
- Anchors verified: `run_daemon_loops` at `src/daemon.rs:520`; WindowCreated arm ~573 does not broadcast; WindowDestroyed arm broadcasts only if actions non-empty; Register and UpdateStatus already broadcast.
- Binding happens in `on_window_created` -> `register_agent_window` (`src/daemon.rs:651`). Binding mutates state silently; the broadcast must live in the loop (where `broadcast_status` is reachable alongside the destroyed arm), not inside `on_window_created`, to keep that pure for its existing unit tests.
- `on_window_created` returns non-empty actions for both an agent bind and an `agent.monitor.*` window of a known agent. The monitor case does not change registry state, so a full-list subscriber gets a duplicate line; diff subscribers are unaffected (unchanged diff is skipped). This is harmless, but see Question 1.
- Windows that match no agent return empty actions, so no broadcast.
- Existing tests that count subscriber lines after a WindowCreated might get an extra line; `test_diff_stream_matches_daemon_state` (line ~1137) and `test_dashboard_subscription_stream` are the ones to watch. Only the targeted commands in the spec are run, so a failure there would be reported under Discovered, not fixed off-plan.
- Constraints honored: scope is `src/daemon.rs` and `tests/integration_tests.rs` only; no wire change (ADR 0008, 0013); no commit; `STATE_28.md` untouched. Base check: HEAD is `de3fc7a`, which contains `17c72ce`.
- Risk: no `pid` on the test window avoids the process-tree-audit path.
